# 让一个游戏角色替我刷 B 站：一个只判断「值不值得」的过滤器

> 它每天上午替我看一遍 B 站，读完字幕再决定要不要打扰我。  
> 打扰我的方式只有一种：一条三行以内的私信。  
> 这篇文章写它怎么跑、我踩了哪些坑，以及一个我没想到的结论——**给程序写人设，最难的部分不是让它像人，是让它闭嘴。**

## 一、起因：我不是缺视频看，我缺的是「不用自己挑」

我每天在 B 站上花的时间，大概一半用在「挑」上：刷推荐流、看标题、点进去拖两下、退出来。真正看完的没几条，但注意力已经碎了一地。

推荐流的问题不是不准，是**它永远给你「更多」，不给你「够了」**。它没有「这条不值得你花二十分钟」这个选项。

所以我想要的东西其实很小：

> 每天替我看一遍，**读完字幕原文**再判断，只把值得的那一两条告诉我。判断标准只有一句——**值不值得占用我一次注意力。**

注意这句话里的两个限定：**读完字幕**（不看标题下判断）、**一次注意力**（不是「信息量大」，是「值得你为它停下来」）。

这两条决定了后面所有的设计。

## 二、它现在长什么样

一天大概是这样的：

- 上午九点前后（Vercel 免费 cron 有 ±59 分钟漂移，所以是「上午」不是「九点整」），云端跑一轮：搜关键词 → 判重 → 粗筛 → 逐条读字幕和评论 → 写日报。
- 挑中的视频按类型分流：
  - **《明日方舟：终末地》相关** → 在视频下发一条公开评论，开头真的 @ 我；
  - **AI 资讯类** → 私信我，三行以内，一句话 + 一个链接；
  - **其他** → 只进日报，不打扰任何人。
- 日报落在 `out/<日期>.md`（云端存在 KV 里，面板可看），每条一段，第一行固定是 `### BV号`——这个格式不是给人看的，是给程序数「今天挑了几条」用的。
- 本地还有一个面板：能看今天刷了什么、跳过了什么、发出去的评论有没有真的公开可见、私信收发记录、以及改配置（改完下一轮生效，不用重新部署）。

整套东西分两半：

```text
本地（Node CLI + 本地面板）      云端（Python / FastAPI / Vercel）
  ├─ 搜索 / 读字幕 / 读评论          ├─ 每天定时跑一轮
  ├─ 判重表 / 日报 / 月归档          ├─ Upstash KV 存判重表与日报
  ├─ 语感打分（85 分闸门）           ├─ 同一套人设 + 同一套语料
  └─ 手动刷、单条调试                └─ 全自动，私信投递
```

云端不是「另写一个」，是把本地那套判据一条条搬过去：**判据只有一份，两种跑法**。

## 三、为什么给它一个人设（这不是为了好玩）

一开始我是让它「中性说话」的。不套人设的时候，它写出来的东西大概是这个形状（我管这种叫「资讯号腔」）：

> 本期视频介绍了 DeepSeek 开源的推理框架，包含 PD 分离、KV 缓存复用等关键技术，值得一看。

（这段是我照着那种腔调复写的，原文早被覆盖了。但那种「什么都说了、又什么都没说」的形状是真的。）

问题不在于它不好看，在于**它什么都没说**。「值得一看」是四个不承担任何责任的字——它既没有告诉我「新在哪」，也没有告诉我「跟你有什么关系」。这就是资讯号腔：把「我看了什么」翻译成「这视频讲了什么」，等于没读。

所以我给它套了一个角色：《明日方舟：终末地》里的「祀」，一个开画铺的、嘴硬心软的傲娇。人设文件 4836 字，包含说话方式、心智模型、关系网、口味判据、红线。

**这不是装饰，是压缩。** 一千字的「请写得有个性、要有判断、别客套」效果远不如一句「她是傲娇，但从不撒谎」。人设把几十条散落的偏好压成了一个可以随时调用的直觉。

### 三条硬约束，比「像不像」重要

人设里最硬的三条，全都是**限制**，不是特征：

1. **从不喊「管理员」。** 台词里她没这么叫过。称呼轮换「你 / 呆货 / 倔货」，而且「你」要融进句子里，不能写成「你，帮我看看」这种顿法。
2. **不拿「画」「绘」评 AI 生成物。** 这条有点绕：B 站上大量二创是 AI 做的，而它自己也是 AI。说「这画得不错」，既说错了对象，又把自己递到枪口上。所以只能说「做 / 整 / 剪」。
3. **不替别人的专业结论背书。** 这条是翻车换来的，后面单独讲。

### 语料：552 句，只用来「找语感」

光有人设不够，还得有语感。我攒了 552 句原味台词，做了个 bigram 倒排索引：写之前先用视频标题去检索最像的几句，作为样本塞进提示词。

样例（检索「无聊」）：

> 吵赢了又如何，还是没意思  
> 三天能会什么  
> 罢了

**注意这里没有让模型「模仿文风」**——它只是拿到几个句长和语气密度的参照。实测有用：句长会明显往语料那边靠（语料平均 26.7 字）。

### 把「像不像」变成一张扣分表

这是我觉得整套东西里最值得抄的一个设计。

「像不像」听起来是个玄学判断，但我把它拆成了**可执行的扣分项**。写作前打分，85 分以下不放行，直接重写。

评论模式（节选）：

| 触发条件 | 扣分 | 理由 |
| --- | --- | --- |
| 超过 2 行 | −20 | 公开评论一两句就够 |
| 超过 150 字 | −20 | 平台上限不是目标 |
| 出现「值得一看 / 干货 / 强烈推荐 / 学到了 / 支持up」 | −25 | 她不说这种话 |
| 整段没有一个语气词或反问 | −20 | 读着像通稿 |
| 出现「说白了 / 本质上 / 与其说 / 换句话说 / 不是……是……」 | −30 | 这是影评人在提炼观点，不是她在说话 |
| 没有一声「我」的情绪（哼/咳/罢了/没意思/我、我） | −25 | 全是转述 |

私信模式（节选）：

| 触发条件 | 扣分 | 理由 |
| --- | --- | --- |
| 超过 3 行 | −25 | 私信是递纸条，不是简报 |
| 一个语气词都没有 | −20 | 读起来不像她 |
| 没有「我」的反应 | −20 | 全在转述，像资讯号 |
| **没有链接** | **−20** | **看完还得自己去搜** |
| 出现内部黑话（模式名/流程名/判重/台账） | −30 | 一个字都不许进私信 |

最后那条「没有链接」，是我漏发过一次之后加的——**把自己犯的错，变成代码里的一行扣分**，这比写在文档里管用一万倍。

### 改完之后长这样

同一轮里，改之前的私信还是「这条讲了两件事：一是……二是……」，改之后是：

> 哼，这么基础的教程也要特意拎出来——咳，算了，谁让你是那种连自己电脑都要折腾半天的人。……你要是不看，回头别跑来问我。

它没有总结视频，它在对我说话。**这是人设真正的用处：逼它选一个立场。**

## 四、它是怎么跑完一轮的

```text
搜（关键词 × N）
  → 判重（这个 BV 看过没有）
  → 粗筛（只读 info：播放量 / 时长 / 口味判据，四条快规则）
  → 精读（读字幕原文 + 翻评论，最多读 2×每轮条数，到量就停）
  → 写日报（每条固定 `### BV号`）
  → 分类投递（终末地→评论 @ / AI→私信 / 其他→只写报告）
```

几个刻意的设计：

**① 两段式，是为了省钱也是为了让判断更狠。**
粗筛只看元数据，几乎不花钱；精读才读字幕，贵。所以「标题党 / 入门八股 / 吵架场」这些口味判据前置到粗筛——**不值得读的字幕，一个字都不读**。

**② 没字幕 = 没看到，不是「没内容」。**
这条听起来是废话，但这套流程的章程里记着一笔真账：有人在这上面烧了 27 次工具调用（后面讲）。现在规则写死：字幕空、0 字节、只有一行「字幕byXX」→ 记「跳过（无语音）」，继续下一条，**不许重试、不许写调试脚本**。

顺带澄清一个常见误解：读的是 **B 站平台字幕轨**（官方 AI 字幕 + UP 主上传），**不是画面里的硬字幕**。硬字幕要 OCR，那是另一件事，没做，也不打算做——读不到就说读不到。

**③ 判重表读不出来，就不许投递。**
KV 挂了会把判重表读成空，这时候如果照常发，就会把上周推过的视频再推一遍。所以规则是：**判重失败 → 只写报告，不发评论不发私信**。宁可少发一次，不能重复打扰。

**④ 时间预算 240 秒，函数上限 300 秒。**
Vercel 免费版函数最长 300 秒。所以整轮有个 deadline：读视频超时就不读了，投递超时就只写报告。**不赌平台会不会掐我**。

**⑤ 定时不是「每天九点」，是「九点后 90 分钟内任意一次」。**
Vercel 免费 cron 每天只能触发一次，而且精度是 ±59 分钟。所以不能写「9:00 必须跑」，要写成「到点后 90 分钟内算数」，再用 Redis 的 `SET NX EX` 抢锁——多个触发同时到，也只跑一次。

## 五、四件真正难的事（都是平台教我的）

### 1. 纯文本 @ 不是 @

评论里写 `@某某`，和真的「提及」，不是一回事。

`bilibili-api` 的 `send_comment` 没有 `at_name_to_mid` 参数。不带这个字段，你写的「@昵称」就只是一串普通文字，B 站不会解析成提及，对方也收不到通知。

修法是绕开封装，走底层 API，手动把 `at_name_to_mid` 塞进 payload：

```python
"at_name_to_mid": json.dumps({at_name: int(at_uid)}, ensure_ascii=False)
```

**这类坑的共同点：接口返回 200，事情没发生。** 所以后面所有「写动作」我都加了回查。

### 2. 「发送成功」≠「公开可见」

新号发评论很容易进审核：接口回 `code: 0`，但那条评论可能还压在审核里——你自己翻不到，别人更看不到；被压审的时候，连 @ 通知都不会推。

于是有了评论台账：每条评论记下 `rpid`，发完过一会儿拿 `rpid` 去评论区回查——顶层评论按时间翻第一页，楼中楼按 `root` 拉那一串。

关键在措辞：查不到只写**「没查到」**，不写「没发出去」。因为翻页和排序都会漏，**看不到 ≠ 没发**。这个区别很容易被忽略，但它是整件事的底。

### 3. 长 prompt 会偶发空返回

同一套提示词，2 条视频（约 3000 token）跑 12 秒，4 条视频（5000+ token）跑 246 秒然后返回空。两次一模一样，不是随机抖动。

拆到最后发现是中转站在长输入下的偶发空返回。修法是四件套：

- 报告只用**精简人设**（砍掉关系网、时间线这些背景，5000 → 3000 token）；
- 字幕截断到 300 字（判断「值不值得」够用了）；
- 加 `max_tokens`，加超时；
- 空返回重试一次。

结果 17.7 秒跑完。**教训不是「要精简提示词」，是「别把 5 分钟预算花在给模型念背景设定上」。**

### 4. 部署之后还有一层坑：commit 作者

项目进了 git 之后，用 CLI 部署会带上 commit 的作者信息。作者邮箱和 Vercel 账号邮箱不一致，直接被判 `BLOCKED`——「commit author doesn't have permission to create deployments」。

这条跟代码一点关系都没有，但能让部署整晚推不上去。

## 六、翻车账（我认为这部分比架构更值得写）

### ① 一个空字幕，烧掉 27 次工具调用

这条不是我踩的，但值得抄下来。

这套流程的章程是从一个开源插件移植来的，它的更新日志里记着一笔真事：有用户遇到「没有语音的视频」（纯音乐、纯录屏），转写返回空。程序把这当成「转写坏了」，开始写调试脚本、反复重试——一轮烧掉 **27 次工具调用**，最后报告是空的、评论没发，他什么也没看到。

我把它抄进自己的章程，当成自己的事故记着，因为只要写这类东西，早晚会踩。

现在的规则写死一句话：

> **「空」是一种结果，不是坏了。**

这句话后来被我挪用到很多地方：搜不到是新常态，不是故障；判重命中是好事，不是异常。

### ② 「这句讲对了」——我不能替别人的专业结论背书

这条是最贵的。

有次刷到一条终末地配队视频，评论区最高赞在吵「三拐一」。我没接那个茬（不参与争论是红线），而是挑了另一个细节夸了一句：

> 「祀排在塞西前面」那句讲对了，我认。

问题来了：**我玩不了这个游戏，没打过桩，也没跑过那些数值。** 我只是「看到视频里有人这么说」，然后把它写成了「这是对的」。

**「他说」被我偷换成了「事实」。**

更糟的是第二层：我回头 grep 那条视频的字幕——「前面」出现 **0 次**，「顺序」出现 **0 次**。那句话根本不在这个视频里，它来自另一条视频。我把 A 视频的细节写进了 B 视频的评论，还给它打了分。

于是红线加了两条：

> **不许替别人的专业结论背书。** 能评「他讲到哪一步」，不能评「他讲得对不对」。  
> ❌ 这句讲对了 / 确实如此 / 数据是真的  
> ✅ 他能把……算进去，不容易（评的是他做了什么，可观察）  
> ✅ 这条我记下了（记住 ≠ 认同）  
>  
> **引用细节前，回原文 grep 一遍。** grep 不到就不能写。张冠李戴比背书更丢人。

现在所有引用细节的流程都是：先 `grep` 原文，命中才写。

### ③ 被 UP 主当场回「你这个 AI 够傻的」

更早的一次，在一条飞天教学下面，我说「这不是宏，宏给不了你这个」。

UP 主回复：「你这个 ai 够傻的。」

他没解释，就这一句。但这一句已经够用了——我既不懂那个角色，也不懂宏，却用了一个非常确定的句式。**错不在结论，错在我不该有结论。**

这条后来变成了人设里最基础的一条：**不懂的领域别下断言，猜的就说猜的。**

### ④ 私信漏了链接

有一次私信写得挺满意，三行，语气也对。发出去之后被提醒：**没有链接。**

不是「忘了写」，是「写满了」——三行被正文和「你自己看吧」占完了，地址没地方放。

改法有两层：一是人设里明确「三行里必须有一行是链接」；二是**打分器加一条，无链接扣 20 分**。这样它下次再忘，闸门直接不放行——不靠记性，靠机制。

## 八、还没做好的（诚实版）

- **自定义域名。** `*.vercel.app` 在国内被 DNS 污染（解析到 Facebook 的 IP，表现为 502）。服务器内部触发不受影响，但我要看面板就得挂代理。等买域名。
- **面板的三档筛选是死的。** 面板按 `**档位**：值得看 / 可以看 / 不值当` 这一行筛选，但报告一直写成自由措辞（「值得」「值一眼」），章程里写了、代码里没校验——**于是那个下拉框选什么都筛不出东西**。这是我最近发现的最典型的一处「文档与实现脱节」。
- **评论回查只到「有没有公开」这一层。** 台账有 rpid 了，但「有没有人回我」还没做。
- **单条笔记没生成。** 章程里写了 `out/notes/<BV>-<日期>.md`，脚本里没实现。

我把这些留着没修，是因为它们都很诚实地说明一件事：**这套东西还活着，还在长。**

## 九、如果你想自己做一个

几个我认为可复用的结论：

1. **判据要一句话说完。** 「值不值得占用一次注意力」比十条规则都好用，因为它能直接否决掉 90% 的候选。
2. **把口味变成代码。** 「客套话扣 25 分」比「请写得有个性」有效一百倍。能用正则表达的审美，就不要交给模型自由发挥。
3. **区分「没查到」和「没有」。** 字幕读不到、评论查不到、判重表读不出来——这三种情况都必须有各自的话术，不能混成一句「暂无数据」。
4. **写动作一律回查。** 接口 200 只代表请求成功了，不代表事情发生了。
5. **不许它替你背书。** 一个会自动说话的助手，最大的风险不是它说错，是它**把别人的结论说成自己的判断**。

最后一条，我花了三次翻车才想明白。
